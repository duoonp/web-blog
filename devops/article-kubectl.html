Easy development without rebuilds: magic of kubectl cp

The Problem

The traditional inner development loop on Kubernetes is brutally slow. If you make a one-line code change, you typically have to build a new Docker image, push it to a registry, update the deployment manifest, and wait for the pod to roll out. This can take minutes for every minor tweak, destroying developer momentum.

The Fix

You can bypass the build-and-push cycle entirely by running a development pod with sleep infinity as its entrypoint (PID 1). This keeps the pod alive without locking the main process.

We can then use a set of bash scripts wrapped around kubectl cp to hot-sync local code changes directly into the running container, stop the old backend process, and spin up the new one in seconds.

The Scripts

1. The Main Router (sync.sh)

This script dictates whether we are just syncing code, just restarting the backend, or doing both.

#!/bin/bash
CONTAINER=$1
ACTION=$2

case $ACTION in
  restart)
   bash scripts/01_sync_code.sh $CONTAINER
   bash scripts/02_restart_backend.sh $CONTAINER restart
  ;;
  code-sync)
   bash scripts/01_sync_code.sh $CONTAINER
  ;;
  backend-restart)
   bash scripts/02_restart_backend.sh $CONTAINER restart
  ;;
esac

2. Code Synchronization (01_sync_code.sh)

This script dynamically finds the pod and copies the local application directory and scripts straight into the container's filesystem.

CONTAINER=$1

POD_NAME=$(kubectl get pod -l "app=$CONTAINER" -o jsonpath="{.items[0].metadata.name}")

kubectl exec -c $CONTAINER $POD_NAME -- mkdir -p /root/.config/mc
kubectl cp -c $CONTAINER ./mc/hotlist $POD_NAME:/root/.config/mc/hotlist

kubectl cp ./app -c $CONTAINER $POD_NAME:/app/
kubectl cp pyproject.toml -c $CONTAINER $POD_NAME:/app/pyproject.toml
kubectl cp ./scripts/start_web_ui.sh -c $CONTAINER $POD_NAME:/app/scripts/start_web_ui.sh
kubectl cp ./scripts/stop.sh -c $CONTAINER $POD_NAME:/app/scripts/stop.sh

echo "Code sync for $CONTAINER completed."
echo ""

3. Backend Restart (02_restart_backend.sh)

Once the fresh code is inside, this script executes a stop command, and then starts the UI/backend as a background process, redirecting logs to the container's standard output so they are still viewable via kubectl logs.

#!/bin/bash

CONTAINER=$1
POD_NAME=$(kubectl get pod -l "app=$CONTAINER" -o jsonpath="{.items[0].metadata.name}")

kubectl exec $POD_NAME -c $CONTAINER  -- bash /app/scripts/stop.sh
echo "Backend stopped for $CONTAINER"

kubectl exec $POD_NAME -c $CONTAINER  -- /bin/sh -c "nohup bash /app/scripts/start_web_ui.sh > /proc/1/fd/1  2> /proc/1/fd/2 &"
echo "Backend restarted for $CONTAINER"
echo ""

echo "Logs:"
echo "kubectl logs -f $POD_NAME -c $CONTAINER"

echo "https://my-service.my-local.domain"
